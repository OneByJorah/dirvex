# dirvex

A read-only Active Directory health dashboard driven by a collector JSON feed.

[![CI](https://github.com/OneByJorah/dirvex/actions/workflows/ci.yml/badge.svg)](https://github.com/OneByJorah/dirvex/actions/workflows/ci.yml)
[![License](https://img.shields.io/github/license/OneByJorah/dirvex?color=FFB300)](LICENSE)

![Running demo dashboard with two synthetic controllers](docs/screenshots/dashboard.png)

## Why this exists

Check replication, SYSVOL, LDAP bind and service states in one place. Dirvex reads a JSON file generated by a collector; it does not query AD itself. The default Docker stack uses synthetic sample data and needs no domain credentials.

## Features

- Controller cards render the feed, including individual service states.
- Each request reloads the feed; collector updates need no app restart.
- Missing, invalid or stale live data reports **Unknown**.
- A minimal status summary uses the same aggregation as the dashboard.
- Non-root, read-only Docker runtime with localhost publishing.
- J1 dark/amber interface and locally served JetBrains Mono font.

There are no uptime measurements, retained trends, live AD probes or notification integrations. Collector scripts are examples; production AD collection has not been verified.

## Quick start — Docker

Requires Docker Engine/Desktop with Compose v2. These commands work in PowerShell and common Unix shells.

~~~sh
git clone https://github.com/OneByJorah/dirvex.git
cd dirvex
cp .env.example .env
docker compose up -d --build --wait
~~~

Open [localhost:5000](http://127.0.0.1:5000). The demo intentionally reports **Degraded** because its synthetic records include stopped services.

~~~sh
docker compose ps
docker compose exec -T dirvex id -u
docker compose down
~~~

The user ID is 10001. The image healthcheck tests /healthz; /readyz separately returns 503 for an unusable or stale feed and 200 for usable healthy or degraded data.

## Configuration

Compose reads .env. Keep credentials in Passbolt; the viewer consumes no AD passwords.

| Variable | Default | Meaning |
| --- | --- | --- |
| HOST_PORT | 5000 | Localhost-only host port |
| DEMO_MODE | true | Sample-data label; static demo timestamps permitted |
| STATUS_DIRECTORY | ./demo | Existing directory containing status.json, mounted read-only |
| STALE_AFTER_SECONDS | 900 | Maximum live-record age; must be positive |
| STATUS_PATH | /data/status.json in Compose | Feed path; direct Python default is mock_dc_status.json |
| MOCK_PATH | unset | Legacy fallback for STATUS_PATH in direct Python runs |

For a real feed, set DEMO_MODE=false and point STATUS_DIRECTORY to a dedicated collector-output directory. A directory mount allows atomic replacement of status.json to become visible. Restrict that directory to the collector and runtime account; do not mount a broad operational-data folder.

The feed is a nonempty JSON array of up to 1,000 records (maximum 1 MiB), using [demo/status.json](demo/status.json). Each record requires string fields Name, Replication, SYSVOL, LDAPBind and LastChecked, plus a nonempty Services mapping of string names to string states. LastChecked must include a timezone. Optional DHCPScope is displayed as supplied.

Healthy requires replication Healthy, SYSVOL OK, LDAPBind Success and every service Running. Other supplied states degrade a controller. In live mode, timestamps older than the configured age or over 60 seconds in the future produce Unknown. Overall: Unknown if any controller is unknown, otherwise Degraded if any is degraded, otherwise Healthy. Invalid files report Unknown; no old successful result is cached.

## Tailscale access

The app has no authentication. Keep it on loopback and use a separately configured, authenticated Tailscale-only access path. The historical /public route name does **not** authorize internet publishing. Do not open inbound firewall ports or use Tailscale Funnel. See [SECURITY.md](SECURITY.md).

## Development

Python 3.13 is the container runtime; local Windows Python 3.12 was also tested.

~~~sh
python -m pip install -r requirements-dev.txt
python -m ruff check app.py tests
python -m ruff format --check app.py tests
python -m pytest -q
~~~

For real screenshots of the running demo:

~~~sh
npm ci
npm run screenshots
~~~

Install the matching Playwright browser first, or set CHROMIUM_PATH to an installed Chrome executable. Captures scan visible text before writing files. See [verification notes](docs/VERIFICATION.md) for executed checks and limitations.
